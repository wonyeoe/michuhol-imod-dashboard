# I-MOD insight

**인천 미추홀구 버스 데이터를 바탕으로 I-MOD 운영 검토 후보를 탐색하는 대시보드**

[대시보드 바로가기](https://michuhol-imod-dashboard.vercel.app/)

공공데이터 활용 AI 데이터 분석 경진대회 프로젝트입니다. 버스 이용·운행 패턴을 분석해 추가 검토가 필요한 지역을 좁히고, 분석 결과와 선정 근거를 지도와 차트로 전달합니다.

## 프로젝트 배경

버스 이용자가 많다는 사실만으로 교통 서비스가 부족하다고 판단할 수는 없습니다. 이 프로젝트는 이용 규모와 함께 **승차·운행의 시간적 분포, 월별 변동, 공간적 위치**를 살펴보고 여러 평가 기준을 종합했습니다.

대시보드는 “어디를 우선 검토해야 할까?”, “어느 시간대에 차이가 나타날까?”, “왜 이 지역이 후보로 선정됐을까?”를 탐색할 수 있도록 구성했습니다. 기존 STEP 1–7 분석 결과 CSV를 활용하며, 웹에서 모델을 재학습하거나 후보 순위를 다시 계산하지 않습니다.

## 분석 범위와 과정

- **지역:** 인천광역시 미추홀구
- **기간:** 2026년 4–6월, 유효 관측일 90일(6월 11일 제외)
- **기본 단위:** 정류장명 그룹 286개 — 물리 정류장 ID와 구분되는 분석 단위

```text
정류장명 그룹 286개 → 공간 검토 그룹 40개 → 평가 권역 26개 → 예비 후보 6개
```

1. **특성 분석:** 승차·운행·시간대별 특성을 정리하고, K-means 등으로 비슷한 특성의 그룹을 분류했습니다.
2. **후보 선별·권역 구성:** 여러 평가 조건으로 후보를 비교한 뒤, 공간 검토 대상 40개 그룹을 Complete Linkage 500m 조건으로 묶어 26개 권역을 구성했습니다.
3. **최종 검토 순서 결정:** 4개 평가 방식의 상위 6위 포함 횟수를 우선 비교하고, 동률이면 순위 중앙값과 균형형 점수를 차례로 적용했습니다.

## 주요 분석 결과

| 검토 순서 | 권역 ID | 구성 정류장명 그룹 | 상위 6위 포함 횟수 |
| --- | --- | --- | --- |
| 1 | Z06 | 롯데백화점(인천터미널) | 4/4회 |
| 2 | Z23 | 남중학교, 인화여고 | 4/4회 |
| 3 | Z10 | 주안7동행정복지센터, 신기.남부종합시장(진흥사거리) | 3/4회 |
| 4 | Z22 | 주안역, 주안역환승정류장 | 2/4회 |
| 5 | Z01 | 문학경기장(야구장) | 2/4회 |
| 6 | Z02 | 문학초등학교 | 2/4회 |

최종 후보 중 승차량이 가장 많은 곳은 Z22이지만, 종합 검토 순서의 첫 후보는 Z06입니다. 단순 승차량 순위와 여러 평가 기준을 종합한 결과가 다르다는 점을 보여 줍니다.

> 최종 6개 권역은 현장 여건을 추가로 확인할 **예비 검토 후보**이며, I-MOD 도입 확정 지역이 아닙니다.

## 대시보드 주요 기능

| 페이지 | 확인할 수 있는 내용 |
| --- | --- |
| **종합 현황** `/` | 분석 규모, 최종 후보 지도·목록·비교표 |
| **시간대별 분석** `/temporal` | 후보별 24시간 승차·운행 비중, 두 비중의 차이, 월별 일평균 |
| **후보 권역 탐색** `/zones` | 26개 권역 검색·필터링, 선택 권역의 특징과 다른 후보와의 비교 |
| **AI 분석 및 선정 근거** `/analysis` | 분석 흐름, 최종 선정 규칙, STEP 1–7의 상세 근거 |

지도·목록·지표를 연동하고, 선택한 후보를 다른 페이지에서도 이어서 확인할 수 있습니다. 핵심 결과를 먼저 보여 주고 기술적 지표와 분석 방법은 펼쳐 보는 상세 영역에 담았습니다. 데스크톱과 모바일 화면을 지원합니다.

## 기술 스택

- **프론트엔드:** React, TypeScript, Vite, React Router
- **UI·시각화:** Tailwind CSS, shadcn/ui, Recharts, React Leaflet
- **데이터·검증:** CSV, Papa Parse, Vitest, Playwright

별도 백엔드나 데이터베이스 없이 기존 분석 CSV를 정적 파일로 제공합니다.

## 데이터 출처와 해석 시 유의점

인천 대중교통 통계 API, 전국 버스정류장 표준정보, 인천 버스노선별 정류장 현황 등 공공데이터를 활용했습니다. 수집·결합 과정은 [연구 정리본](docs/연구%20정리본/연구%20정리본%20565b43a48dc58234a95f01b21f9dd2ba.md)에 정리되어 있습니다.

- 승차·운행 비중의 차이는 **시간 분포의 차이**이며, 실제 공급 부족이나 미충족 수요를 직접 입증하지 않습니다.
- 최대 비중 차이 시간은 최대 승차량 시간 또는 I-MOD 최적 운영시간과 다릅니다.
- 500m는 그룹 대표점 사이의 최대 거리 조건이며, 실제 서비스 반경이 아닙니다.
- 현장 접근성, 차량 수용력, 이동 경로와 실제 도입 효과는 추가 검토가 필요합니다.

## 로컬 실행

Node.js **22.12 이상**에서 저장소 전체를 내려받은 뒤 실행합니다. 분석 CSV가 상위 폴더에 있으므로 `dashboard/`만 따로 복사하지 않습니다.

```bash
cd dashboard
npm ci
npm run dev
```

빌드는 `npm run build`, 단위·통합 테스트는 `npm test`로 실행합니다. 실행·빌드 시 필요한 최종 CSV는 자동으로 동기화되며 원본 분석 파일은 변경하지 않습니다.

## 저장소 구성

```text
dashboard/         웹 애플리케이션·테스트·개발 문서
COLAB code/        AI 모델링 및 데이터 분석 Notebook
dataset/           전처리·분석용 CSV
STEP별 결과 파일/  단계별 분석 결과와 시각화
docs/              연구 과정·결과 문서
```

원천 자료 `dataset_raw/`와 대용량 시간대별 데이터는 Git에서 제외합니다. 데이터 연결 방식, 테스트·빌드 및 배포 설정은 [개발 README](dashboard/README.md)에서 확인할 수 있습니다.
