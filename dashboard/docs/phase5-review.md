## 지표 표현과 해석 범위

- `positive_gap_sum`: **승차·운행 시간 분포 차이**. 시간별 승차 비중−운행 비중 중 **양수만 합산**한 값이며, 원본의 0–1 척도를 유지한다. %p 값으로 바꾸어 표시하지 않는다.
- `monthly_cv`: **월별 승차량 변동 정도**. 3개월 일평균 승차량의 표본 표준편차(ddof=1)÷평균. 작을수록 해당 기간의 변동이 작으며 미래 안정성을 보장하지 않는다.
- 월별 최소/최대 비율: 가장 적은 달의 일평균÷가장 많은 달의 일평균. 선택 권역에서 백분율로도 뜻을 설명하되 원본 비율을 함께 유지한다. CV와 구분한다.
- `median_rank`: **평가 방식별 순위 중앙값**. 4개 순위를 정렬했을 때 가운데 두 값의 평균이다.
- `top6_frequency`: 4개 시나리오 중 **상위 6위 포함 횟수**. 도입 효과나 확률을 나타내지 않는다.
- 최대 상대 격차: 승차 비중−운행 비중의 양의 차이가 가장 큰 시간. 승차량 최대 시간, 실제 공급 부족 또는 I-MOD 최적 운행시간으로 해석하지 않는다.

예를 들어 기본 선택 Z06은 18시에 승차 비중 10.22%, 운행 비중 5.24%, 차이 4.98%p로 설명된다. 문장 속 값은 선택 권역 데이터에서 가져오며 상수로 넣지 않았다. %p는 두 백분율의 차이라는 설명과, 운행 건수에 차량 정원·혼잡도·타지 못한 승객 정보가 없다는 한계를 함께 표시한다.

기술 설명은 네이티브 `details/summary`로 제공한다. 마우스 호버 없이 키보드 Enter와 모바일 클릭으로 산식·정확한 시나리오 점수·24시간 수치를 확인할 수 있다. 기존 히트맵과 차트 툴팁도 유지한다.

## 데이터 정확성 검수

| 항목 | 확인 결과 |
| --- | --- |
| 기간·관측일 | 2026년 4–6월, 90일. 6월 11일 제외. 월별 30/31/29일 |
| 분석 단위 | 정류장명 그룹 286개. 원본 물리 정류장 502개는 고유 `station_id`로 별도 확인 |
| 공간 단위 | 40개 후보 그룹 → Complete Linkage 500m의 26개 권역. 다중 그룹 12개·단일 그룹 14개 |
| 최종 검토 순서 | Z06 → Z23 → Z10 → Z22 → Z01 → Z02 유지 |
| 페이지 간 일치 | 종합 현황·시간대별·권역 탐색의 일평균, 최대 차이 시간·%p 교차 검증 |
| 월별 지표 | 실제 월별 일평균에서 최소/최대 비율과 표본 CV를 계산해 저장값 검증 |
| 시간 분포 차이 | 시간별 양의 차이(%p) 합÷100과 저장된 `positive_gap_sum` 일치 |
| 시나리오 | 전체 26개 × 4개 점수·순위, 최종 6개 포함 횟수·중앙값을 원본 CSV와 대조 |
| 누락·0 | 기존 누락·중복·좌표·수치 검증 유지. 실제 0과 결측을 구분하며 필수 누락은 오류 표시 |

시간별 승차 비중의 분모는 **선택 권역 구성 그룹의 90일·24시간 누적 승차량**, 운행 비중의 분모는 **같은 권역·기간의 누적 운행 건수**다. 두 분모는 서로 다르다. 그룹별 비중이나 일별 비중의 평균이 아니다. 월별 일평균은 월 누적값÷각 월의 관측일 수이며, 3개월 평균을 단순 평균해 90일 일평균으로 사용하지 않는다.

500m는 구성 그룹 대표점 사이 **최대 거리 조건**이다. 운행 반경, 도로 거리, 행정 경계로 표시하지 않는다. 그룹 ID와 물리 정류장 ID를 결합하지 않았다. 원본 분석 결과 간 새로운 불일치는 발견되지 않았다.

## 파일과 데이터 연결

기존 13개 CSV 동기화·로더·검증 코드를 그대로 사용한다. 원본 CSV, Notebook, STEP 1–7 결과는 수정하지 않았다. 배포 데이터 사본은 총 230,015바이트이며 기존 원본 대조 검증을 유지한다.

- 공통 후보·지표: STEP 7 `05_provisional_top6_review.csv`, `04_all_26_zones_scenario_scores.csv`.
- 시간·월별: STEP 7 `03_hourly_zone_shares.csv`, `02_monthly_zone_profiles.csv`.
- 권역 구성·좌표: STEP 6 `05_complete500_assignments.csv`, `06_complete500_zone_profiles.csv`.
- 군집·과정: 기존 STEP 3 할당·프로필·모델 지표, STEP 4 적격성, STEP 6 알고리즘 비교 CSV.
- 물리 정류장 개수 확인: `dataset_raw/3. 미추홀구 버스 정류장.csv`. 테스트에서만 읽으며 브라우저 배포 파일로 추가하지 않았다.

수정 파일은 `src/components/layout.tsx`, `src/index.css`, 4개 페이지, `components/overview/`, `components/zones/`, `components/analysis/`의 표시 컴포넌트, `temporal-charts.tsx`와 공통 상태 화면이다. 작은 보조 글자의 크기·명도를 조정했다. `package.json`에 최종 브라우저 검수를 연결하고 `README.md`에 이 보고서 링크를 추가했다.

새 파일:

- `tests/integration.test.ts`: 페이지 간 지표 일치·물리 정류장 ID 검증 2개.
- `tests/final-ux-browser.mjs`: 제거 요소, 동적 문장, URL 유지, 접근성, 모바일 넘침과 8개 최종 캡처.
- `docs/phase5-review.md`: 이 완료 보고서.

## 검증 및 실행

- `npm test`: 기존 38개 유지, 추가 2개 포함 **40개 통과**.
- `npm run build`: TypeScript와 Vite 프로덕션 빌드 통과.
- `npm run test:browser`: 종합 현황·시간대별·권역·분석 및 최종 UX 검수. 최종 빌드의 로컬 미리보기에서 Chrome으로 실행.
- 1536px 데스크톱·390px 모바일에서 네 페이지 진입·새로고침·지도·차트·내부 표 스크롤 확인. 기존 시간대별 검수는 1440px도 포함한다.
- CSV HTTP 오류·재시도·빈 자료·중복·누락, 지도 타일 실패 중 후보 선택 유지 등 기존 오류 경로 회귀 검수.
- 6개 후보의 동적 설명을 시간별 CSV와 비교. `?zone=Zxx` 선택·새로고침·페이지 간 전달 검증. 시간대별 선택 시 URL도 갱신하도록 최소 개선했다.
- 최종 정상 탐색에서 JavaScript 및 콘솔 오류 없음. 자세한 자동 결과는 `test-results/final-ux-report.json`.

```powershell
cd dashboard
npm run dev
# 프로덕션 확인은 별도 터미널에서:
npm run build

$env:DASHBOARD_URL='http://127.0.0.1:4177'
```

## 남은 범위

확인된 기능 회귀나 데이터 불일치는 없다. 모바일 검수는 Chrome의 390px 뷰포트 기준이며 실제 iOS Safari·스크린리더 전수 검증을 대신하지 않는다. 지도 배경은 외부 타일 네트워크에 의존하며 오류 안내와 재시도 기능을 유지한다. 제출 전 실제 심사 화면과 기기에서 최종 확인을 권장한다. OD·차량 수용력·현장 접근성·운영 효과는 기존 데이터로 검증할 수 없어 새로 추정하지 않았다.
